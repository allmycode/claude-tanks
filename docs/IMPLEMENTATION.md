# Детали реализации

Как устроена игра «Танки». Что и зачем делалось — в [PLAN.md](PLAN.md).

## Файлы и архитектура

```
index.html   клиент: отрисовка, звук, клавиатура, меню, сетевой клиент
game.js      логика игры без DOM — общая для браузера и сервера
server.js    Node.js: HTTP (раздаёт index.html и game.js) + WebSocket-комнаты
package.json зависимость ws, скрипт npm start
```

`game.js` оформлен как UMD: в браузере он кладёт API в `window.Tanks`, в Node — в `module.exports`.
Главная функция — `createGame(opts)`, она возвращает:

| Член | Назначение |
| --- | --- |
| `G` | всё состояние игры (игроки, враги, пули, карта, таймеры, текущая фаза) |
| `startGame(twoPlayers)` | новая игра с 1-го уровня |
| `tick(dt)` | шаг симуляции на `dt` секунд |
| `setInput(playerId, dir, fire)` | текущее управление игрока: направление 0–3 или -1, огонь |
| `togglePause()` | пауза |

Логика не играет звуки и не рисует эффекты сама — она вызывает `opts.emit(type, ...args)`:

| Событие | Аргументы | Что делает клиент |
| --- | --- | --- |
| `sfx` | имя звука | играет звук |
| `boom` | x, y, big | взрыв с частицами |
| `debris` | x, y, цвет | осколки (кирпич, бетон, гусеница) |
| `popup` | x, y, текст | всплывающие очки |
| `shake` | сила | тряска экрана |

В одиночной игре `emit` сразу вызывает обработчик клиента. На сервере события копятся и уходят клиентам вместе со снимком состояния.

Клиент рисует объект `V` («вид»). В локальной игре `V` — это само `game.G`, в сетевой — объект с теми же полями, собранный из снимков сервера. Поэтому отрисовка одна для обоих режимов.

## Поле и координаты

- Поле 624×624 px: 52×52 клетки по 12 px (`CELL`, `N`). Танк — 48×48 px, то есть 4×4 клетки.
- Типы клеток: `0` пусто, `1` кирпич, `2` бетон, `3` вода, `4` кусты, `6` штаб.
- Карта хранится в `Uint8Array` (`G.grid`), индекс `r * N + c`.
- Направления: `0` вверх, `1` вправо, `2` вниз, `3` влево; смещения в `DX`/`DY`.
- Штаб в клетках 24–27 × 48–51 (`BASE_X = 288`, `BASE_Y = 576`), точки появления врагов вверху на x = 0, 288, 576, игроков — x = 192 и 384 внизу.

## Генерация уровней (`genLevel`)

Уровень задаётся зерном `level * 7919 + 13` для генератора `mulberry32`, поэтому каждый уровень всегда одинаков.

1. Случайные «стенки» (горизонтальные и вертикальные полосы) кирпича, бетона, воды и кустов. Всё зеркалится по горизонтали — карта симметрична. Доля бетона растёт с уровнем: `min(0.1 + lv·0.015, 0.22)`.
2. Отдельные кирпичные блоки 4×4 и мелкие бетонные блоки.
3. Расчистка: точки появления врагов и игроков, зона вокруг штаба.
4. «Смягчение» проходов: под точками появления врагов и в колонках игроков бетон и вода заменяются кирпичом, чтобы никто не оказался заперт.
5. Кирпичное кольцо вокруг штаба (`setRing`).
6. Бетонное прикрытие от прямого прострела: горизонтальный блок 8×2 над штабом (иногда второй выше) и вертикальные стенки 2×6 по бокам в нижнем ряду.

Проверено скриптом на уровнях 1–15: ни одна линия огня до штаба (сверху и вдоль нижнего ряда) не свободна от бетона.

## Движение и столкновения

- Танк двигается шагами по 1 px (`moveTank`); каждый шаг проверяется через `blocked`.
- Непроходимы кирпич, бетон, вода, штаб и края поля. Другой танк блокирует только если пересечение появилось бы заново — так танки, появившиеся внахлёст, могут разъехаться.
- При повороте на 90° координата поперёк нового направления округляется до 24 px (полтайла), если это не приводит к столкновению. Так танк точно попадает в проходы шириной 48 px.

## Пули и разрушение

- Пуля — квадрат 6×6, летит подшагами по 4 px, чтобы не проскакивать стены.
- Попадание в кирпич или бетон сносит полосу шириной с танк (4 клетки) в первом ряду, где есть что ломать (`impact`). Кирпичная стена толщиной 2 клетки пробивается за два выстрела.
- Бетон ломается только пулей с `power >= 2` (игрок с тремя звёздами).
- Встречные пули игрока и врага взаимно уничтожаются. Пули врагов пролетают сквозь врагов, пули игроков не ранят другого игрока.

## Правило гусеницы (`isTrackHit`)

Попадание в танк делится на два случая:

- пуля летит **вдоль** оси танка (в лоб или в спину) и её поперечное смещение от центра танка не меньше 11 px — это торец гусеницы: `stunTank` обездвиживает танк на `STUN_TIME = 3` с;
- иначе (по центру корпуса или **в борт**) — обычное попадание: игрок гибнет, враг теряет единицу брони.

Обездвиженный танк не едет и не поворачивает, но стреляет. Повторное попадание в гусеницу просто перезапускает таймер. Сторона повреждения (`stunSide`) запоминается для отрисовки. Каска защищает и от этого.

## Враги

| Тип | Скорость | Скорость пули | Броня | Очки |
| --- | --- | --- | --- | --- |
| обычный | 48 | 260 | 1 | 100 |
| быстрый | 100 | 300 | 1 | 200 |
| скорострельный | 58 | 450 | 1 | 300 |
| броневик | 46 | 300 | 4 | 400 |

- Очередь из 20 врагов на уровень (`buildQueue`); доля сильных типов растёт с уровнем.
- Одновременно на поле не больше 4 врагов (6 при игре вдвоём). Появление — после анимации звезды, если место свободно.
- ИИ (`enemyAI`): едет в текущем направлении; по таймеру или упёршись меняет направление — 40% к штабу, 25% к случайному живому игроку, остальное случайно. Если игрок или штаб на линии огня — стреляет почти сразу, упёршись в стену — стреляет чаще.

## Бонусы

| Бонус | Эффект |
| --- | --- |
| каска | неуязвимость 10 с |
| звезда | +1 уровень танка (до 3) |
| граната | уничтожает всех врагов на поле |
| часы | враги замирают на 10 с |
| лопата | кольцо штаба из бетона на 18 с (последние 3 с мигает) |
| танк | +1 жизнь |

Бонус всегда один на поле и исчезает через 18 с. Подбор даёт 500 очков.

## Фазы игры

`G.state`: `intro` (заставка уровня, 2 с) → `play` → `done` (уровень пройден, 4 с, затем следующий) или `dying` (штаб разрушен или игроки без жизней, 3 с) → `over`.
Меню, экран подключения и ожидание соперника — это режимы клиента (`mode`: `menu`, `connect`, `local`, `net`), в логике их нет.

## Клиент (`index.html`)

- **Отрисовка:** canvas масштабируется под окно с учётом devicePixelRatio. Тайлы — спрайты 12×12, нарисованные в коде; карта кэшируется в отдельный canvas и перерисовывается только при изменении (`gridVer`) и для анимации воды. Кусты лежат в отдельном слое поверх танков. Танки рисуются векторно, с анимацией гусениц.
- **Звук:** Web Audio, всё синтезируется (тоны и отфильтрованный шум), аудио включается по первому нажатию клавиши.
- **Управление:** стек нажатых направлений на игрока — едем в последнем нажатом. Раздельные WASD/стрелки только при игре вдвоём за одним компьютером, в остальных режимах работают обе раскладки.
- **Рекорд:** `localStorage` (`tanks-hiscore`), последний адрес сервера — `tanks-server`.
- **Дым** от перебитой гусеницы порождается на клиенте по полю `stun`, а не событиями с сервера.

## Сеть

### Сервер (`server.js`)

- Один порт (по умолчанию 8080, переменная `PORT`) для HTTP и WebSocket. По HTTP отдаются только `index.html` и `game.js`.
- Лобби: первый клиент ждёт (`wait`), второй создаёт с ним комнату. У каждой комнаты свой экземпляр `createGame` с `trackChanges: true`.
- Комната тикает по `setInterval` с периодом 1000/60 мс, `dt` меряется по `process.hrtime`. После каждого тика оба клиента получают снимок.
- Если игрок отключился, комната закрывается, второй получает `left` и возвращается в лобби.
- Раз в 10 с ping/pong; не ответившие соединения закрываются.

### Протокол (JSON)

Клиент → сервер:

| Сообщение | Смысл |
| --- | --- |
| `{t:'in', d, f}` | направление (-1…3) и огонь (0/1); отправляется только при изменении |
| `{t:'pause'}` | пауза для обоих |
| `{t:'restart'}` | новая игра после проигрыша |

Сервер → клиент:

| Сообщение | Смысл |
| --- | --- |
| `{t:'wait'}` | ожидание второго игрока |
| `{t:'start', slot}` | игра началась, `slot` — номер своего танка (0 или 1) |
| `{t:'left'}` | соперник отключился |
| `{t:'s', ...}` | снимок состояния |

Снимок (`snapshot` в `server.js`) — компактные массивы, координаты округлены до 0.1:

| Поле | Содержимое |
| --- | --- |
| `st`, `stT`, `lv`, `pa`, `fr`, `ba`, `q` | фаза, её таймер, уровень, пауза, заморозка, жив ли штаб, очередь врагов |
| `pl` | игроки: `[alive, x, y, dir, lives, score, level, shield, stun, stunSide, anim]` |
| `en` | враги: `[x, y, dir, type, hp, bonus, stun, stunSide, anim, id]` |
| `bu` | пули: `[x, y, dir, isPlayer, id]` |
| `pu` | бонусы: `[type, x, y, timeLeft]` |
| `sr` | x точек появления врагов |
| `g` | вся карта строкой из 2704 цифр — при старте уровня |
| `gc` | изменения карты `[index, value, ...]` с прошлого снимка |
| `ev` | события `emit` за тик |

### Плавность

Таймер Node на Windows срабатывает с шагом около 15,6 мс, поэтому реально приходит около 35 снимков в секунду. Клиент интерполирует позиции танков и пуль от прошлого снимка к текущему (`withPrev`, `interpolate`), сопоставляя объекты по `id`; при скачке больше 40 px (возрождение) позиция ставится сразу. Это добавляет задержку отображения примерно в один интервал снимков.

## Ограничения

- Нет предсказания движения на клиенте: при большом пинге управление ощущается с задержкой.
- Нет выбора соперника — пары составляются по порядку подключения.
- Сервер доверяет клиенту только направление и огонь; другого ввода не принимает, размер сообщения ограничен 4 КБ.
- Проверено на одном компьютере (браузер + бот-клиент); игра двух разных компьютеров по сети не проверялась.
