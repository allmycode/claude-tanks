# Детали реализации

Как устроена игра «Танки». Что и зачем делалось — в [PLAN.md](PLAN.md).

## Файлы и архитектура

```
index.html   клиент: отрисовка, звук, клавиатура, меню, сетевой клиент
game.js      логика игры без DOM — общая для браузера и сервера
stages.js    карты и составы врагов 35 уровней оригинальной Battle City
server.js    Node.js: HTTP (раздаёт index.html, game.js, stages.js) + WebSocket-комнаты
config.json  настройки сервера: проценты выпадения бонусов
package.json зависимость ws, скрипт npm start
```

`game.js` оформлен как UMD: в браузере он кладёт API в `window.Tanks`, в Node — в `module.exports`.
Главная функция — `createGame(opts)`, она возвращает:

| Член | Назначение |
| --- | --- |
| `G` | всё состояние игры (игроки, враги, пули, карта, таймеры, текущая фаза) |
| `startGame(twoPlayers, fromLevel = 1)` | новая игра с указанного уровня |
| `tick(dt)` | шаг симуляции на `dt` секунд |
| `setInput(playerId, dir, fire)` | текущее управление игрока: направление 0–3 или -1, огонь |
| `togglePause()` | пауза |

Логика не играет звуки и не рисует эффекты сама — она вызывает `opts.emit(type, ...args)`:

| Событие | Аргументы | Что делает клиент |
| --- | --- | --- |
| `sfx` | имя звука | играет звук |
| `boom` | x, y, big | взрыв с частицами |
| `debris` | x, y, цвет | осколки (кирпич, бетон, гусеница) |
| `popup` | x, y, текст | всплывающие очки |
| `shake` | сила | тряска экрана |

В одиночной игре `emit` сразу вызывает обработчик клиента. На сервере события копятся и уходят клиентам вместе со снимком состояния.

Клиент рисует объект `V` («вид»). В локальной игре `V` — это само `game.G`, в сетевой — объект с теми же полями, собранный из снимков сервера. Поэтому отрисовка одна для обоих режимов.

## Поле и координаты

- Поле 624×624 px: 104×104 клетки по 6 px (`CELL`, `N`). Танк — 48×48 px, то есть 8×8 клеток.
- Уровень размечается на более крупной сетке 52×52 по 12 px (`LC`, `LN`), а затем каждая клетка разметки превращается в 2×2 клетки игры. Мелкая клетка нужна, чтобы выстрел снимал четверть стенки.
- Типы клеток: `0` пусто, `1` кирпич, `2` бетон, `3` вода, `4` кусты, `5` лёд, `6` штаб.
- Лёд проходим для танков и пуль. Игрок, отпустив управление на льду, ещё `ICE_SLIDE = 0.3` с едет по инерции (около 34 px); враги не скользят.
- Карта хранится в `Uint8Array` (`G.grid`), индекс `r * N + c`.
- Направления: `0` вверх, `1` вправо, `2` вниз, `3` влево; смещения в `DX`/`DY`.
- Штаб в клетках 48–55 × 96–103 (`BASE_X = 288`, `BASE_Y = 576`), точки появления врагов вверху на x = 0, 288, 576, игроков — x = 192 и 384 внизу.

## Уровни (`genLevel`)

Уровни 1–35 — оригинальные карты Battle City (`classicLayout`). Дальше, как в оригинале, карты идут по кругу с 1-й (уровень 36 — карта 1, 71 — снова карта 1), а враги на каждом новом круге сильнее (`lapOf`): до +10% скорости за круг (максимум +40%) и часть врагов в очереди заменена на следующий по силе тип (25% за круг, максимум 75%).
Генератор (`randomLayout`) остался запасным вариантом на случай, если `stages.js` не загружен.
Обе функции заполняют сетку разметки 52×52, затем `genLevel` растягивает её до 104×104 и ставит кольцо штаба.

### Оригинальные уровни (`stages.js`)

- Данные карт и составов врагов взяты из MIT-проекта [feichao93/battle-city](https://github.com/feichao93/battle-city) (`src/stages/stage-N.json`); текст лицензии — в шапке `stages.js`.
- Карта — 13 строк по 13 тайлов. Тайл — 4×4 клетки разметки: кирпич задаётся с точностью до клетки разметки (четверть четверти тайла), бетон — до четверти тайла, лес, вода, лёд и штаб — целым тайлом. Формат расписан в шапке `stages.js`.
- Враги выходят в том порядке и составе, что в оригинале (`bots`, например `18*basic, 2*fast`); бонусные танки — 4-й, 11-й и 18-й, как и раньше.
- В оригинальных картах нет дополнительного бетонного прикрытия штаба: они воспроизводятся как есть.
- Проверено скриптом: все 35 карт клетка в клетку совпадают с эталонным разбором (`parseStage.ts` исходного проекта, перенесён один к одному), очереди врагов — тоже.

### Сгенерированные уровни (запасной вариант)

Уровень задаётся зерном `level * 7919 + 13` для генератора `mulberry32`, поэтому каждый уровень всегда одинаков.
Шаги 1–4 и 6 работают на сетке разметки 52×52 (размеры ниже — в её клетках), потом карта растягивается до 104×104, и уже на ней ставится кольцо штаба (шаг 5).

1. Случайные «стенки» (горизонтальные и вертикальные полосы) кирпича, бетона, воды и кустов. Всё зеркалится по горизонтали — карта симметрична. Доля бетона растёт с уровнем: `min(0.1 + lv·0.015, 0.22)`.
2. Отдельные кирпичные блоки 4×4 и мелкие бетонные блоки.
3. Расчистка: точки появления врагов и игроков, зона вокруг штаба.
4. «Смягчение» проходов: под точками появления врагов и в колонках игроков бетон и вода заменяются кирпичом, чтобы никто не оказался заперт.
5. Кирпичное кольцо вокруг штаба (`setRing`).
6. Бетонное прикрытие от прямого прострела: горизонтальный блок 8×2 над штабом (иногда второй выше) и вертикальные стенки 2×6 по бокам в нижнем ряду.

Проверено скриптом на уровнях 1–15: ни одна линия огня до штаба (сверху и вдоль нижнего ряда) не свободна от бетона.

## Движение и столкновения

- Танк двигается шагами по 1 px (`moveTank`); каждый шаг проверяется через `blocked`.
- Непроходимы кирпич, бетон, вода, штаб и края поля. Другой танк блокирует только если пересечение появилось бы заново — так танки, появившиеся внахлёст, могут разъехаться.
- При повороте на 90° координата поперёк нового направления округляется до 24 px (полтайла), если это не приводит к столкновению. Так танк точно попадает в проходы шириной 48 px.

## Пули и разрушение

- Пуля — квадрат 6×6, летит подшагами по 4 px, чтобы не проскакивать стены.
- Попадание в танк считается по пересечению квадрата пули с танком, а не по её центру. Иначе встречные танки в соседних полосах (сдвиг ровно 24 px из-за выравнивания при повороте) простреливали бы друг мимо друга: центр пули шёл точно по краю гусеницы.
- Попадание в кирпич или бетон сносит полосу шириной с танк (8 клеток, 48 px) и глубиной в одну клетку (6 px) в первом ряду, где есть что ломать (`impact`). То есть выстрел снимает четверть стенки в полтайла (24 px): тонкая стенка пробивается за 4 выстрела, блок толщиной в тайл (48 px) — за 8.
- Бетон ломается только пулей с `power >= 2` (игрок с тремя звёздами).
- Встречные пули игрока и врага взаимно уничтожаются. Пули врагов пролетают сквозь врагов.
- Пуля игрока, попавшая в напарника, его не убивает, а, как в оригинале, замораживает на `PARTNER_FREEZE = 3` с: танк мигает и не может ехать, но стреляет. Каска от этого защищает.

## Правило гусеницы (`isTrackHit`)

**Сейчас выключено** флагом `TRACK_HITS = false` в `game.js`: любое попадание поражает танк, как в оригинальной игре.
Код правила и отрисовка перебитой гусеницы оставлены — чтобы вернуть, достаточно поставить `TRACK_HITS = true`. Ниже — как правило работает во включённом виде.

Попадание в танк делится на два случая:

- пуля летит **вдоль** оси танка (в лоб или в спину) и её поперечное смещение от центра танка не меньше 11 px (и до 26 px, где пуля ещё задевает край танка) — это торец гусеницы: `stunTank` обездвиживает танк на `STUN_TIME = 3` с;
- иначе (по центру корпуса или **в борт**) — обычное попадание: игрок гибнет, враг теряет единицу брони.

Обездвиженный танк не едет и не поворачивает, но стреляет. Повторное попадание в гусеницу просто перезапускает таймер. Сторона повреждения (`stunSide`) запоминается для отрисовки. Каска защищает и от этого.

## Враги

| Тип | Скорость | Скорость пули | Броня | Очки |
| --- | --- | --- | --- | --- |
| обычный | 48 | 260 | 1 | 100 |
| быстрый | 100 | 300 | 1 | 200 |
| скорострельный | 58 | 450 | 1 | 300 |
| броневик | 46 | 300 | 4 | 400 |

- Очередь из 20 врагов на уровень (`buildQueue`): как в оригинале, на следующих кругах — с усилением (см. «Уровни»).
- Одновременно на поле не больше 4 врагов (6 при игре вдвоём). Появление — после анимации звезды, если место свободно.
- ИИ (`enemyAI`, `enemyMove`, `pickDir`), ближе к оригиналу:
  - враг едет до следующей границы полутайла (24 px) и только там может сменить направление (раз в 0,6–2,2 с); упёршись больше чем на 0,25 с, выбирает другое направление;
  - доля поворотов к штабу растёт со временем уровня (`G.stageTime`): от 20% в начале до 70% примерно через 75 с; к игроку — до 25%, остальное случайно;
  - если игрок или штаб на линии огня — стреляет почти сразу, упёршись в стену — стреляет чаще.

## Бонусы

| Бонус | Эффект |
| --- | --- |
| каска | неуязвимость 10 с |
| звезда | +1 уровень танка (до 3) |
| граната | уничтожает всех врагов на поле |
| часы | враги замирают на 10 с |
| лопата | кольцо штаба из бетона на 18 с (последние 3 с мигает) |
| танк | +1 жизнь |

Бонус всегда один на поле и исчезает через 18 с или когда выходит следующий бонусный танк (как в оригинале). Подбор даёт 500 очков.
Тип выбирается по весам. По умолчанию это `PU_WEIGHTS`: звезда — 1,3, остальные — 1, то есть звезда выпадает примерно в 20,6% случаев, остальные — по 15,9%.
Свои веса передаются в `createGame({ powerupWeights })`; их проверяет `sanitizeWeights`: неизвестные бонусы отбрасываются, неуказанные, отрицательные и нечисловые считаются 0, при нулевой сумме берутся значения по умолчанию. Сумма не обязана быть 100 — веса нормируются.

Очки и жизни: за 20 000 очков (`EXTRA_LIFE_SCORE`) один раз даётся дополнительная жизнь. Стартовый рекорд — 20 000.

## Фазы игры

`G.state`: `intro` (заставка уровня, 2 с) → `play` → `done` (уровень пройден, `DONE_TIME = 8` с, затем следующий) или `dying` (штаб разрушен или игроки без жизней, 3 с) → `over`.

В фазе `done` после паузы `TALLY_DELAY = 1,5` с клиент показывает табло, как в оригинале (`drawTally`): по строке на каждый тип врага — сколько уничтожил каждый игрок и сколько это очков, строки появляются по очереди с «досчётом» и щелчками, затем «ВСЕГО». Счёт ведётся в `p.kills[тип]`; враги, уничтоженные гранатой, не засчитываются. При игре вдвоём тот, кто уничтожил больше врагов, получает 1000 очков (`G.tallyBonus` — номер игрока или -1 при равенстве).
Меню, экран подключения и ожидание соперника — это режимы клиента (`mode`: `menu`, `connect`, `local`, `net`), в логике их нет.

## Клиент (`index.html`)

- **Отрисовка:** canvas масштабируется под окно с учётом devicePixelRatio. Тайлы — спрайты 12×12, нарисованные в коде; карта кэшируется в отдельный canvas и перерисовывается только при изменении (`gridVer`) и для анимации воды. Кусты лежат в отдельном слое поверх танков. Танки рисуются векторно, с анимацией гусениц.
- **Звук:** Web Audio, всё синтезируется (тоны и отфильтрованный шум), аудио включается по первому нажатию клавиши.
  - Мотор (`updateEngine`): постоянный пилообразный гул с модуляцией через фильтр; когда свой танк едет — выше и чаще. Звучит в фазах `play` и `done`, пока жив хотя бы один свой танк; молчит на паузе и при выключенном звуке.
  - Перед уровнем — своя короткая мелодия (ведущий голос и бас), не копия оригинальной.
- **Отрисовка тайлов:** спрайты нарисованы 12×12, а клетка 6×6, поэтому для каждой клетки берётся нужная четверть спрайта по чётности строки и столбца — рисунок кирпича и бетона остаётся цельным.
- **Выбор уровня:** в меню ←/→ (A/D, крестовина или стик) меняют стартовый уровень 1–35 по кругу (`startStage`); он действует для игры на одном компьютере.
- **Управление:** стек нажатых направлений на игрока — едем в последнем нажатом. Раздельные WASD/стрелки только при игре вдвоём за одним компьютером, в остальных режимах работают обе раскладки.
- **Геймпад:** Gamepad API, опрос `navigator.getGamepads()` каждый кадр (`readPads`), стандартная раскладка. Движение — крестовина или левый стик (порог 0,5, побеждает бо́льшая ось), огонь — A/B/X/Y/RB/RT, Start — пауза и «ОК», Back/Select — выход. В меню выбор крестовиной или стиком, подтверждение A или Start; в окне адреса A — подключиться, B — назад (`padActions`, срабатывает на нажатие). Назначение (`padFor`): при игре вдвоём за одним компьютером два геймпада — по одному на игрока, один — второму игроку; в одиночной и сетевой игре любой геймпад управляет своим танком. Клавиатура работает одновременно с геймпадом, геймпад приоритетнее по направлению.
- **Рекорд:** `localStorage` (`tanks-hiscore`), последний адрес сервера — `tanks-server`.
- **Дым** от перебитой гусеницы порождается на клиенте по полю `stun`, а не событиями с сервера.

## Сеть

### Сервер (`server.js`)

- Один порт (по умолчанию 8081, переменная `PORT`) для HTTP и WebSocket. По HTTP отдаются только `index.html`, `game.js` и `stages.js`. Сетевая игра всегда начинается с 1-го уровня.
- Лобби: первый клиент ждёт (`wait`), второй создаёт с ним комнату. У каждой комнаты свой экземпляр `createGame` с `trackChanges: true`.
- Комната тикает по `setInterval` с периодом 1000/60 мс, `dt` меряется по `process.hrtime`. После каждого тика оба клиента получают снимок.
- Если игрок отключился, комната закрывается, второй получает `left` и возвращается в лобби.
- Раз в 10 с ping/pong; не ответившие соединения закрываются.
- Настройки (`loadConfig`): `config.json` рядом с `server.js` или путь из `TANKS_CONFIG`. Читается при запуске и при старте каждой комнаты (если текст файла изменился — разбирается заново и в консоль печатаются проблемы и итоговые проценты). Сейчас там один раздел — `powerups` (проценты бонусов, формат — в README); он передаётся в `createGame` как `powerupWeights`. При отсутствии файла или ошибке JSON — значения по умолчанию.

### Протокол (JSON)

Клиент → сервер:

| Сообщение | Смысл |
| --- | --- |
| `{t:'in', d, f}` | направление (-1…3) и огонь (0/1); отправляется только при изменении |
| `{t:'pause'}` | пауза для обоих |
| `{t:'restart'}` | новая игра после проигрыша |

Сервер → клиент:

| Сообщение | Смысл |
| --- | --- |
| `{t:'wait'}` | ожидание второго игрока |
| `{t:'start', slot}` | игра началась, `slot` — номер своего танка (0 или 1) |
| `{t:'left'}` | соперник отключился |
| `{t:'s', ...}` | снимок состояния |

Снимок (`snapshot` в `server.js`) — компактные массивы, координаты округлены до 0.1:

| Поле | Содержимое |
| --- | --- |
| `st`, `stT`, `lv`, `pa`, `fr`, `ba`, `q` | фаза, её таймер, уровень, пауза, заморозка, жив ли штаб, очередь врагов |
| `pl` | игроки: `[alive, x, y, dir, lives, score, level, shield, stun, stunSide, anim, frozen, kills]` |
| `tb` | кому достался бонус за уровень (0, 1 или -1) |
| `en` | враги: `[x, y, dir, type, hp, bonus, stun, stunSide, anim, id]` |
| `bu` | пули: `[x, y, dir, isPlayer, id]` |
| `pu` | бонусы: `[type, x, y, timeLeft]` |
| `sr` | x точек появления врагов |
| `g` | вся карта строкой из 10 816 цифр (104×104) — при старте уровня |
| `gc` | изменения карты `[index, value, ...]` с прошлого снимка |
| `ev` | события `emit` за тик |

### Плавность

Таймер Node на Windows срабатывает с шагом около 15,6 мс, поэтому реально приходит около 35 снимков в секунду. Клиент интерполирует позиции танков и пуль от прошлого снимка к текущему (`withPrev`, `interpolate`), сопоставляя объекты по `id`; при скачке больше 40 px (возрождение) позиция ставится сразу. Это добавляет задержку отображения примерно в один интервал снимков.

## Ограничения

- Нет предсказания движения на клиенте: при большом пинге управление ощущается с задержкой.
- Нет выбора соперника — пары составляются по порядку подключения.
- Сервер доверяет клиенту только направление и огонь; другого ввода не принимает, размер сообщения ограничен 4 КБ.
- Проверено на одном компьютере (браузер + бот-клиент); игра двух разных компьютеров по сети не проверялась.
- Геймпад проверен эмуляцией Gamepad API; на реальном контроллере не проверялся. Контроллеры без стандартной раскладки (`mapping !== 'standard'`) могут иметь другие номера кнопок.
- Браузер отдаёт геймпад странице только после первого нажатия на нём кнопки.
